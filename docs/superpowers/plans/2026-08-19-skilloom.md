# Skilloom implementation plan

**Goal:** Ship a public, installable CLI and guided terminal interface that reconciles global and project Agent Skills through the `skills` CLI on Node.js and Bun.
**Source:** [Skilloom design](../../plans/2026-08-19-skilloom-design.md)
**Approach:** Build one TypeScript package around a pure desired-state core, a constrained `skills` process adapter, scriptable commands, and lightweight Clack workflows. Develop each behavior test-first and keep Git synchronization behind a small adapter.
**Scope:** Version 1 includes local configuration, managed or external config paths, profiles, machine selection, project manifests, plan/apply/status/update/init/project-init/config/doctor commands, JSON output, and Node/Bun packaging. It excludes npm publication, a browser UI, SSH orchestration, background services, Windows claims, and direct configuration-manager integrations.
**Key risks:** The upstream `skills list --json` shape and lockfile behavior may change, user configuration may be partially invalid, and apply can fail midway. Isolate upstream parsing, validate every external value, preserve failure output, recompute plans after partial execution, and test against captured fixtures plus packaged smoke tests.
**Completion:** A fresh clone installs with npm or Bun, all checks pass under both runtimes, the packaged CLI can initialize a temporary home/project, plan and apply through a fake `skills` executable, documentation covers the workflows, and the public repository contains CI plus an npm-ready package without publishing it.

## File and contract map

- `package.json`, `tsconfig.json`, `tsup.config.ts`, `biome.json`, `vitest.config.ts`: package metadata, runtime support, build, lint, and test contracts.
- `src/core/config.ts`, `src/core/schema.ts`: versioned user and project configuration parsing, defaults, and actionable validation failures.
- `src/core/resolve.ts`, `src/core/plan.ts`: pure profile resolution, scope handling, normalization, and deterministic drift plans.
- `src/adapters/skills.ts`: the only adapter allowed to invoke `npx skills`; parses list output and constructs safe argument arrays.
- `src/adapters/git.ts`: managed-config clone, pull, status, commit, and push behavior without destructive conflict resolution.
- `src/cli/*`: command definitions, text/JSON rendering, exit codes, confirmation rules, and dependency injection.
- `src/tui/*`: guided menus built with `@clack/prompts`, delegating behavior to the same command services.
- `tests/fixtures/*`: representative upstream JSON and configuration fixtures.
- `tests/integration/*`: temporary-home and fake-executable tests.
- `README.md`, `LICENSE`, `CONTRIBUTING.md`: public installation, concepts, configuration, automation, security, and contribution guidance.
- `.github/workflows/ci.yml`: Node and Bun verification plus package smoke tests.

Contracts that must remain aligned are the YAML schemas and schema version, CLI help and README examples, planner operations and process adapter arguments, JSON output and exit-code documentation, npm `bin` metadata and build output, and CI runtime versions.

## 1. Package foundation and executable contract

**Files:** Root package/configuration files, `src/index.ts`, initial CLI help tests
**Contracts:** `skilloom` npm name and binary; ESM output; Node and Bun entry points; macOS/Linux support

- Add the package metadata, MIT license, TypeScript strict settings, Biome, Vitest, tsup, and scripts for test, typecheck, lint, build, and package smoke tests.
- Define the executable entry point and top-level Citty command tree with stable command names and placeholder handlers that fail clearly until their services exist.
- Add injected runtime boundaries for environment, filesystem roots, clock, process execution, and terminal interactivity so tests never touch real user state.

**Verification:**

- Write and run failing tests for `--help`, `--version`, unknown commands, and JSON-mode error envelopes before implementing the entry point.
- Run `bun test`, typecheck, lint, build, and execute the built `dist/index.mjs --help` with Node and Bun.

**Complete when:** The built package exposes the documented command tree under both runtimes and no test accesses the real Skilloom or agent directories.

## 2. Versioned configuration and project manifests

**Files:** `src/core/schema.ts`, `src/core/config.ts`, `src/core/paths.ts`, configuration fixtures and unit tests
**Contracts:** `~/.config/skilloom/config.yaml`, `SKILLOOM_CONFIG`, `.skilloom.yaml`, schema version, machine identity, storage modes

- Define minimal versioned Zod schemas for global profiles, machine assignments, managed/external/local storage metadata, project profiles, committed project requirements, agent targets, and personal project additions.
- Resolve XDG and macOS paths consistently while honoring an explicit config path argument and `SKILLOOM_CONFIG`.
- Parse YAML with source-aware errors, reject unknown or unsafe values, and write deterministic YAML without dropping comments when no semantic change is required.
- Generate a stable local machine identifier without committing host-specific paths into shared configuration.

**Verification:**

- Test valid examples, missing files, defaults, unknown versions, duplicate skill entries, invalid agents, unsafe repository identifiers, environment overrides, and round trips.
- Run focused configuration tests after each red-green cycle.

**Complete when:** Valid configuration loads into normalized typed data, invalid configuration returns a file/path-aware diagnostic, and project manifests cannot introduce commands or arbitrary executable arguments.

## 3. Desired-state resolver and deterministic planner

**Files:** `src/core/resolve.ts`, `src/core/plan.ts`, resolver/planner unit tests
**Contracts:** Additive project policy; global/project separation; deterministic operations; idempotency; stable JSON representation

- Resolve global profile, machine assignment, reusable project profile, committed project requirements, and personal additions in the documented order.
- Normalize sources, skill names, and agent targets, deduplicate equivalent requirements, and surface incompatible declarations instead of picking silently.
- Compare desired state with installed state and produce sorted add/remove operations. Project cleanup only removes skills previously managed by Skilloom; it never deletes an unrelated installation.
- Include enough provenance in each operation for the TUI and JSON output to explain why the change exists.

**Verification:**

- Test each precedence boundary, additive project behavior, duplicate collapse, unrelated installed skills, conflict diagnostics, deterministic ordering, and an empty plan after simulated apply.
- Use snapshots only for the stable public JSON plan, with direct assertions for behavioral rules.

**Complete when:** The same inputs always produce the same plan, a converged state produces no operations, and unrelated user-managed skills are preserved.

## 4. Safe `skills` CLI adapter and execution

**Files:** `src/adapters/skills.ts`, `src/services/apply.ts`, upstream fixtures, adapter and integration tests
**Contracts:** All mutations go through `npx skills`; no shell interpolation; exact scope and agent flags; partial-failure reporting

- Query project and global state with `npx skills list --json` and `npx skills list --global --json`, validating output behind an upstream adapter schema.
- Translate planner operations into argument arrays for `npx skills add`, `remove`, and `update`, including `--global`, `--agent`, `--skill`, and `--yes` only where appropriate.
- Execute without a shell, stream human output when interactive, capture structured results for JSON mode, and redact environment values.
- Stop safely on failure, return completed and pending operations, and require a fresh plan before retry.

**Verification:**

- Start with failing command-construction and process tests using a fake `npx` executable on `PATH`.
- Test spaces and metacharacters in paths, rejected source identifiers, missing `npx`, malformed upstream JSON, nonzero exits, cancellation, partial completion, and idempotent retry.

**Complete when:** Integration tests prove every mutation is represented by an expected `npx skills` argv sequence and malicious configuration cannot become shell syntax.

## 5. Scriptable commands and terminal workflows

**Files:** `src/cli/*`, `src/tui/*`, command and interaction tests
**Contracts:** `init`, `plan`, `apply`, `status`, `update`, `project init`, `config`, `doctor`; `--yes`; `--json`; exit codes

- Implement command services once, then expose them through Citty and Clack rather than duplicating logic.
- Make `skilloom` open a guided menu only on an interactive terminal. In non-interactive contexts it prints help and exits without hanging.
- Add readable plan grouping by global/project scope, reason, source, and target agent.
- Make `apply` confirm changes unless `--yes` is present. Make `plan --check` distinguish converged, drifted, invalid, and execution-failure states with documented exit codes.
- Implement `doctor` checks for runtime, Git, `npx`, upstream `skills` availability, config validity, repository state, and project discovery.

**Verification:**

- Test every command in text and JSON mode, TTY and non-TTY behavior, cancellation, empty states, narrow output, and all exit-code branches.
- Run a bounded manual terminal pass after automated verification.

**Complete when:** Users can complete the local-only global and project workflow interactively or entirely through flags, and automation never encounters an unexpected prompt.

## 6. Git-backed configuration modes

**Files:** `src/adapters/git.ts`, `src/services/sync.ts`, init/config workflows, Git integration tests
**Contracts:** Managed Git, external file, and local-only modes; existing credentials; no destructive conflict handling

- Implement local-only initialization first, then external-config selection, then managed Git clone/connect/pull/commit/push.
- Keep GitHub-specific repository creation optional through `gh`; accept any clone URL for normal operation.
- Refuse managed pulls or writes when the configuration checkout has uncommitted conflicting changes. Never reset, force-push, or auto-merge.
- Record no credentials and avoid embedding access tokens in stored remote URLs.

**Verification:**

- Use local bare repositories to test first clone, existing clone, clean pull, commit/push, offline failure, dirty worktree, divergent history, and token-like URL rejection.
- Verify external and local-only modes never invoke Git.

**Complete when:** Two temporary machine homes can share a profile through a bare Git remote, converge independently, and preserve conflicts for manual resolution.

## 7. Public documentation, CI, and release readiness

**Files:** `README.md`, `CONTRIBUTING.md`, `LICENSE`, examples, `.github/workflows/ci.yml`, package metadata
**Contracts:** Public commands and config examples; Node/Bun support claims; npm package contents; no publication

- Write a concise README covering the problem, quick start, storage modes, global profiles, project manifests, exact `npx skills` delegation, automation, and why Skilloom complements dotfiles, Ansible, and Nix.
- Add complete example configurations and explain additive project policy, managed-skill cleanup, lockfiles, security, and recovery from partial apply.
- Configure CI for Node and Bun tests, typecheck, lint, build, and packed-package smoke tests.
- Inspect `npm pack --dry-run` output and ensure only necessary files ship. Reserve actual npm publication for explicit approval.

**Verification:**

- Run the complete local verification suite from a clean install.
- Run `npm pack --dry-run`, install the tarball into a temporary project, and exercise help, init, plan, doctor, and project init under Node and Bun.
- Confirm the GitHub repository is public and CI configuration targets `main`.

**Complete when:** A new contributor can follow the README from a fresh clone, the packed artifact works under both runtimes, and no credentials, machine paths, or generated test state appear in Git.

## Cross-cutting verification

- Focused unit tests run throughout each test-first implementation cycle.
- The full test suite, typecheck, Biome check, and production build must pass immediately before any completion claim.
- Packaged tests use the exact tarball contents rather than the source tree.
- Manual verification covers both `npx` and `bunx` invocation paths where package installation permits.
- Inspect `git diff --check`, repository status, package contents, and public configuration examples before pushing.
- Do not publish npm, enable telemetry, create remote-machine SSH access, or mutate installed global skills during verification.

## Rollout and completion

Version 1 ships as source and an npm-ready package in the public GitHub repository. The first release can be tagged and published only after the user confirms the package name remains available and authorizes npm publication.

If upstream `skills` output differs from the captured fixtures, update only the adapter and its compatibility tests. If Bun exposes runtime differences, retain the Node-compatible implementation and fix or document the narrow incompatibility before claiming Bun support.

Repository-wide completion requires the planned commands, local and Git-backed workflows, automated tests, Node/Bun smoke evidence, public documentation, CI, and a clean pushed `main` branch. Remote-machine clones are operational follow-up and require reachable SSH hostnames or another authorized connection method.
